# xym

Generic NixOS images for machines that relay public VPN traffic, and the
`nix run` installer that configures one and writes it to a disk. A Nix flake on
[haraspkgs](https://github.com/haras-unicorn/haraspkgs).

## Structure

- `src/nix/modules/` has the NixOS modules of the image, one file per concern.
  They are exported as `nixosModules` and every image imports all of them. They
  switch on the tagged options `xym.hardware` and `xym.vpns`.
- A hardware or a VPN registers itself in `self.lib.hardware.<name>` or
  `self.lib.vpns.<name>`, in the same file as its module. The options, the image
  builds and the installer all read those entries through `selfLib`. The paths
  inside the image where the installer writes user configuration are
  `self.lib.inject.<name>`, in the file of the module that reads them.
- `src/nix/images.nix` defines `makeSystem`, `makeToplevel` and `makeImage`,
  which take the values of the `xym.hardware` and `xym.vpns` options. They are
  exported per system as `lib.<system>`, and the installer builds images and
  updates devices through them. Images stay uncompressed, and the device keeps
  Nix so it can be rebuilt.
- `src/nix/docs.nix` builds the mdbook and the generated options page, and
  `src/nix/dev.nix` is the dev shell.
- `src/nix/xym/` holds the installer. `xym.nu` is one Nushell script in three
  sections: TUI, CLI and EXT. The TUI only asks and calls the CLI. The CLI
  decides. Only EXT calls external commands, and it also honors `XYM_FAKE` and
  `XYM_DRY_RUN`.
- `src/nix/tests/` has the container tests. Unit tests sit next to the code.
- `docs/` is the mdbook: only `book.toml`, the summary, an introduction that
  includes anchored sections of `README.md`, and the generated options page.

## Development

Enter the dev shell through direnv or `nix develop`. Run `dev format` and
`dev check`. `dev fake` previews the TUI with fake data.

The options page, `docs/options.md`, is generated from the options module by
`dev format` and compared by `dev check`. The license, code of conduct,
`.gitignore` and `.gitattributes` are generated by the dev module. Edit
`src/nix/dev.nix` and not those files.

## Deviations

- Images are built with `nixosSystem` directly and not with the haraspkgs
  machine registry. The registry puts the nixpkgs source into every machine, and
  these images must stay lean.
- Reading the NixOS modules back through `config.flake.nixosModules` is how the
  images and tests get at them. Nothing in the repository is a machine.
